Part 6

The research loop in depth

Part 5 took one study round the loop. This part goes further into each stage, for when you need it: your own data and databases, SQL, interactive notebooks, citations, and talking back to the agent in the review.

In this part
  • The notebook’s data view
  • Data files, SQL and your own databases
  • “What if?” sliders
  • Citations and grammar
  • Notes and replies in the review
  • Coming back to a project

Notebooks

Every notebook opens with your data straight under the code that made it, as a table you can explore without writing any code.

Your data and databases

Files. Data files go in data/: CSV, Excel, Parquet, or your existing SPSS and Stata files. Python reads them all; ask the agent to load one into the notebook.

SQL. If you’d rather ask questions in SQL, a notebook cell can be SQL instead of Python. It can query the tables already in the notebook, files in data/ directly (FROM 'data/survey.csv'), or a database. The answer is another table you can search and sort, and the cells after it can use it.

Your own database. To work with a Postgres, MySQL, SQLite or other database, choose Add database connection in the notebook’s left-hand panel, or ask the agent to set it up. The database’s tables then appear in that panel, ready to query. Keep the password out of the notebook: put it in a file called .env in the project folder (for example DB_PASSWORD=…) and have the connection read it from there. marimo loads .env when the notebook starts, and Git ignores it, so the password never ends up in a saved version or on GitHub.

The command line. The terminal in the analysis tab is there for everything else: database tools such as psql or duckdb, cloud tools such as AWS’s aws, and ssh to log in to a university computing cluster.

Try ideas with a slider

Notebooks can be interactive too. Here the agent added a slider for how much stress costs: drag it, and the simulation and the fit run again at once. It’s a quick way to see how sensitive a result is before you commit to an analysis.

Why this beats an output window. In SPSS or Stata the analysis happens in one place, the results pile up in another, and the explanation lives in your head or a separate document. A notebook keeps all three together, in order, so it reads like a lab notebook that keeps itself up to date. Six months later you can see exactly how every number was made. Because each notebook is plain text, the review tab shows every change to it line by line. To run the whole notebook from start to finish, for example after changing the software, type uv run analysis/01-explore.py in the analysis tab’s terminal, or ask the agent to.

Writing: citations and grammar

Citations. With Zotero open, type \ci in the paper (press \ then c then i, not in typing mode) and Zotero’s search box appears. Pick a paper and its citation, such as [@knuth1984], appears at the cursor. The reference list builds itself.

Grammar. Spelling and grammar suggestions appear as you write, from a checker called Harper that runs on your own computer.

Notes and replies in the review

The review tab shows every line that has changed since you last saved a version. You don’t approve changes one at a time. You read them, and if something looks wrong or raises a question, you say so, right on the line.

In the review tab, move to the line with j (down) and k (up), press c, type your note and press Ctrl + S to save it. Then tell the agent in the work tab: “I left a comment in Hunk. Reply to it there.” It reads your note and answers underneath it, on the same line. If you ask for a change, it makes it and the review updates. Press a to show or hide the agent’s notes.

Coming back tomorrow

Open the Omarchy menu, choose Projects and pick your project. Everything comes back as you left it: the editor, the agent with your conversation, the console and the PDF builder. Even after you restart the computer, opening the project from the menu starts each tab’s program again.

To back the project up as you go, ask the agent once to “create a private GitHub repository for this project and push it”. After that, “commit and push” saves a version and backs it up in one go.
