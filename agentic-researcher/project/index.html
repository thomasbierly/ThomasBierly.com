Part 2

One project, from data to paper

An agent can only work with what it can read. In the usual setup the analysis lives in an SPSS output window, the paper in Word, the references in EndNote and the old versions in Dropbox. The agent can’t see across them, and often neither can you.

The fix is to keep the whole project as plain files in one folder: the code that makes the data, the analysis, and the paper, which is built straight from the analysis. That’s what makes the agent useful from start to finish, and it’s what makes your work easy to check.

In this part
  • Where mistakes come from in the usual setup

Compared with SPSS, Stata and Word

SPSS, Stata and Word are good tools, and you may have used them for years. The problems come from the gaps between them. Results travel from the statistics package to the paper by copy and paste, and every paste is a chance for the paper to fall out of step with the analysis. These mistakes are easy to make and hard to spot. A spreadsheet error in an influential economics paper on public debt went unnoticed for three years. A 2016 study found that about one in five genetics papers that shared gene lists as Excel files had gene names corrupted by Excel’s automatic formatting.

In this setup the paper is built from the analysis, so there is nothing to paste. Here is how everyday tasks compare:

If you already write Stata do-files or SPSS syntax rather than clicking through menus, you’re halfway there: that is the same idea. Your agent can translate those files into Python and check that they give the same results, and Python opens your existing .sav and .dta files directly. Stata and SPSS both have Linux versions, if your field expects a particular procedure.

Saved versions, and what GitHub is for

Two names come up again and again in this course: Git and GitHub. They replace paper_final_v7.docx, and they’re a big part of why work with an agent is safe.

Git keeps saved versions of the whole project. Whenever you reach a point worth keeping, you save a version (a commit) with a short description, such as “added stress to the simulation”. Each version is a snapshot of every file at once: the code, the data, the notebooks and the paper. You can see exactly what changed between any two versions, line by line, and go back to any of them. Git runs on your own computer, and the agent can do all of it for you when you ask.

GitHub is a website that keeps a copy of those versions online. Each project becomes a repository there, private unless you choose otherwise. You send your latest versions to it with one step (a push), or ask the agent to. A free account is all you need.

A backup with a history

If your laptop is lost or broken, every version of every project is safe online. Unlike a plain backup, you can also go back to how things were last March.

Working with co-authors

Invite them to the repository instead of emailing attachments. Everyone works on the same project, and every change shows who made it and why.

Replication, ready when asked

When the paper is accepted, make the repository public: code, data and the history behind every result. Zenodo can archive it with a DOI so it can be cited.

It also makes the agent safe to work with. Its changes sit on top of your last saved version, so anything you don’t like is one step from being undone, and the version history is the record of how the work was done that part 1 recommends keeping.

What it’s like to use

Most of the day is plain English. You describe what you want, the agent does the mechanical part, and you check what it did. Here are some things you might ask it, at each stage of a project:

Getting the data in

Open survey_export.sav, keep the variables in the codebook, and save a clean copy in data/.

Here’s my old SPSS syntax. Rewrite it in Python and show me that the means match.

Analysis

Regress score on sleep and stress, controlling for year, and explain the output as you would to a reviewer.

Make Figure 2 colour-blind friendly and in APA style.

Writing

Check every number in the Results section against the analysis.

Make a Word version of the paper for my co-author.

Housekeeping

Save a version called “added stress factor” and back it up to GitHub.

The PDF preview stopped updating. Can you find out why?

You stay the researcher. The agent makes changes and explains them, the review tab shows you exactly what it changed, and you can question any line. The same project structure works for a thesis, a grant proposal, a literature review or a course you teach: anything that turns data and reading into writing.
